2. KEY THEORETICAL COMPONENTS
================================================================================

RICHARDS EQUATION (Dimensionless Form):
∂S_e/∂t̃ + ∂q̃/∂z̃ + S̃ = 0

Where:
- S_e = effective saturation ∈ [0,1]
- q̃ = -K̃(∂h̃/∂z̃ + 1) (dimensionless flux)
- S̃ = root uptake sink term

VAN GENUCHTEN-MUALEM RELATIONS:
- Water retention: S_e(h) = [1 + (α|h|)^n]^(-m)
- Relative conductivity: K_r = Se^l × [1 - (1 - Se^(1/m))^m]²
- Storage: C = dS_e/dh

NORMALIZATION (CRITICAL):
- All terms scaled to O(1) for numerical stability
- Time scale: T = θ_* L / K_* (length × water content span / conductivity)
- Head scale: H_* = L
- Conductivity scale: K_* = K_s (saturated)
- Essential for fine-tuning (preserves time scale across datasets)

BOUNDARY CONDITIONS:
1. Surface (Dirichlet): θ0(t) from observations (first depth in YAML)
2. Water table head: h = 0 at z_b
3. Water table kinematic: dz_b/dt = q / S_y
4. Initial conditions: 3 types (obs, linear, hydrostatic)

LOSS FUNCTIONS (6 Components):
1. PDE residual (interior points)
2. Surface BC (moisture observation)
3. Water table head BC (h = 0)
4. Water table kinematic BC (water balance)
5. Initial condition (head)
6. Initial condition (water table depth)

All weighted adaptively using gradient-based log-space updates.

================================================================================
3. SAMPLING STRATEGIES (ADVANCED)
================================================================================

COLLOCATION POINTS (Interior):
- Direct sampling: no cache
- Time: Uniform[0, t_max]
- Depth: Normalized u ∈ [0,1], mapped to z = -u × z_b(t)
- Boundary concentration: 70% near boundaries (Beta distributions)

GRADIENT-BASED BC SAMPLING (KEY INNOVATION):
- File: src/gradient_based_sampling.py
- Purpose: Focus samples where boundary condition changes rapidly

THREE-WAY STRATEGY:
1. Gradient-Interpolated (80%):
   - Compute |dθ0/dt| at BC points
   - Identify high-gradient intervals (top 30% percentile)
   - Create interpolated points within intervals (α ∈ [0,1])
   - Weight by |dθ0/dt|^power

2. Neighbor Points (5%):
   - Points adjacent to high-gradient regions
   - Vectorized tensor operations (no Python loops)

3. Baseline (15%):
   - Uniform random from all BC times
   - Ensures coverage in low-gradient regions

GPU OPTIMIZATION:
- Fully vectorized (no .item() in inner loop)
- Single batched CPU sync at end
- Deferred gradient computation
- Handles spiky/sharp BC transitions naturally

INITIAL CONDITION SAMPLING:
- Time: fixed at t_min
- Depth: Random u ∈ [0, 1], z_ic = -u × z_b(t_min)

================================================================================
4. MODEL ARCHITECTURE & PINN IMPLEMENTATION
================================================================================

NEURAL NETWORKS:
- PressureHeadNet: 2-input (z_scaled, t_scaled) → scalar h̃
  Architecture: Linear → Tanh → [Linear → Tanh] × layers → Linear
  Typical: 64 hidden units, 4 layers (can adjust for domain size)

- WaterTableNet: 1-input (t_scaled) → scalar z̃_b > 0
  Same architecture, 32 hidden units, 3 layers
  Output: Softplus ensures z_b > 0

INPUT SCALING:
- z_scaled = (z_tilde + z_max) / z_max (maps [-1,0] to [0,1])
- t_scaled = t_tilde / t_ref_tilde (maps time to [0,1])

RICHADSPINN CLASS (Main Model):
Public API (accepts dimensional inputs):
- pde_residual(z, t) → PDE interior residual
- surface_moisture_bc_residual(t) → BC residual
- water_table_head_residual(t) → h = 0 at water table
- water_table_kinematic_residual(t) → dz_b/dt = q/S_y
- initial_conditions_residual(z, t0) → IC enforcement
- predict_head(z, t) → dimensional h(z,t)
- predict_water_table(t) → dimensional z_b(t)

AUTOMATIC DIFFERENTIATION:
- PyTorch autograd for all PDE derivatives
- Creates computation graph through first & second derivatives
- Enables training via residual minimization

5. TRAINING METHODOLOGY
================================================================================

MAIN TRAINING FUNCTION:
train_pinn_pool_batch_autoweight() (train_loop.py:21-452)

TRAINING LOOP (Pseudo-code):
```
for epoch in range(n_epochs):
    1. Sample collocation points (direct, no cache)
    2. Sample BC points (gradient-based 3-way)
    3. Sample IC points
    4. Compute 6 loss components
    5. Apply adaptive weights (log-space update)
    6. Backprop + optimizer step
    7. Update weights (every 100-10000 epochs)
    8. Save checkpoint (every 10000 epochs)
```

OPTIMIZER:
- Adam (PyTorch)
- Learning rate: 1e-4 to 5e-4 typical
- Epochs: 10k-50k typical

ADVANCED FEATURES (HPC):
- Mixed Precision (AMP): fp16 for memory efficiency
- Multi-GPU: torch.nn.DataParallel auto-detection
- Gradient Accumulation: effective batch scaling
- Checkpointing: resume from intermediate epochs

ADAPTIVE WEIGHT MANAGEMENT:
- WeightManager class (training_utils.py)
- Algorithm:
  1. Compute unweighted per-sample gradients
  2. EMA smoothing (α=0.9)
  3. Target = median of EMA gradients
  4. Log-space multiplicative update
  5. Cap per-update jump (max_step_factor=2.0)
  6. Clamp bounds [1e-10, 1e10]
- Prevents single loss component from dominating

CHECKPOINTING & RESUMPTION:
- Saved every 10k epochs: model, optimizer, weights, metadata
- Includes normalization params (CRITICAL for fine-tuning)
- Resume with: finetune_pinn(checkpoint_path, new_data)
- Preserves time scale T across datasets

METRICS & MONITORING:
- Per-component loss tracked
- Sample loss computed every 500 epochs (over 5k points)
- Gradient norms per component
- TrainingLogger for CSV/JSON export

9. GRADIENT-BASED SAMPLING IN DETAIL
================================================================================

MOTIVATION:
Traditional uniform BC sampling treats all boundary points equally.
Gradient-based sampling concentrates where boundary condition changes rapidly.

IMPLEMENTATION STEPS:
1. Compute temporal gradient: dθ/dt = Δθ / Δt
2. Normalize by sum: weights = |dθ/dt| / Σ|dθ/dt|
3. Identify high-gradient intervals (top percentile)
4. Allocate samples:
   - 80% from interpolated within high-gradient intervals
   - 5% from neighbors of high-gradient regions
   - 15% from uniform baseline
5. GPU optimize: vectorized, single sync at end

BENEFITS:
- Captures spiky/sharp BC transitions naturally
- Data-driven: adapts to actual BC characteristics
- GPU-efficient: fully vectorized implementation
- Improved convergence near BC inflection points

10. NORMALIZATION & DIMENSIONAL ANALYSIS
================================================================================

WHY NORMALIZE:
Dimensional PDE has mixed scales (O(10^-5) to O(10^-7)).
Networks struggle with such disparate magnitudes.

SOLUTION:
Choose characteristic scales to make all terms O(1):
- L: domain depth
- T = θ_* L / K_*: time scale
- H_* = L: head scale
- K_* = K_s: conductivity scale

RESULT: All PDE terms ~ O(1) in dimensionless form

IMPLEMENTATION:
NormalizationHelper class provides:
- normalize_z, normalize_t, normalize_h
- denormalize_z, denormalize_t, denormalize_h
- Se_tilde(h_tilde): dimensionless saturation
- K_tilde(h_tilde): dimensionless conductivity

CRITICAL FOR FINE-TUNING:
Time scale T preserved from base model ensures:
- Networks see same relative durations
- Weights transfer meaningfully
- Only BC data changes, not fundamental scales

15. SUMMARY
================================================================================

This is a production-ready PINN system for solving the Richards equation with
moving water table boundaries. The key innovation is gradient-based adaptive
boundary condition sampling, which concentrates training samples where the
boundary condition changes most rapidly.

The YAML-driven architecture allows training on new datasets without any code
changes. All physics is parameterized through configuration files, making the
system highly flexible and reproducible.

The unified PINNDataset container provides a clean API for data access, while
the modular architecture separates concerns (models, losses, sampling, logging).

Multi-depth support with automatic adaptation makes it easy to work with
different observation networks. Fine-tuning capability enables transfer learning
across time periods with the same site.

Production features include checkpointing for fault tolerance, multi-GPU support,
mixed precision training, and comprehensive logging for reproducibility.
